# LinkAI 复刻工程实施方案（框架优先版）

> 项目：复刻 LinkAI 一站式 AI 智能体平台
> 核心理念：**平台做框架，用户做创造**。智能体只是框架运行出来的产物，不是平台要逐一实现的功能——平台把能力框架搭好，用户自行创造智能体、知识、工具、流程和内容，生态自生长。
> 配套文档：《linkai-功能拆解与复刻蓝图.md》（对标物全貌参考）。

# 第一部分 核心理念与平台边界

## 1.1 平台做什么，用户创造什么

复刻的不是"9 个算命智能体 + 22 个模板"这些**内容**，而是生产这些内容的**框架**。

| 维度 | 平台负责（框架） | 用户创造（内容） |
|---|---|---|
| 模型 | 统一模型网关、多厂商适配、计费降级 | 选择/切换模型、带自己的 Key |
| 提示词 | 编辑器、变量系统、一键优化、版本管理、评测工具 | 应用设定（人设/流程/约束）、分享模板 |
| 知识 | 导入管道、解析、分段、检索全参数化 | 上传私有知识库 |
| 工具 | 内置通用工具集、MCP 协议、自定义插件机制 | 开发/贡献自己的插件 |
| 流程 | DAG 引擎、节点体系、变量系统 | 编排自己的工作流 |
| 渠道 | 全渠道适配器、消息模型、流式输出 | 一键接入，无需开发 |
| 分发 | 模板中心、应用广场、分类搜索推荐 | 发布应用/模板/灵感 |
| 变现 | 版本配额、积分钱包、收益结算 | 公开应用赚收益 |

**判断标准**：一个功能如果是在"生产内容"，属于用户；如果是在"让用户能生产内容"，属于平台。智能体（含超级 AI 助理）是用户用框架生产出来的东西，平台只需保证框架完整、可扩展、可治理。

## 1.2 框架设计的五条原则

1. **适配器模式贯穿始终**：模型、渠道、文档解析器、工作流节点、插件——所有"品类"都是适配器，加品类=加适配器，不动内核
2. **全参数化**：检索阈值、分段长度、温度、上下文、执行策略……框架参数全部暴露给用户，平台不预设"最佳值"
3. **注册中心**：插件注册表、节点注册表、模板注册表、渠道注册表，统一注册/发现/版本管理
4. **治理内置**：审核、配额、质量分、排行榜算法是框架的一部分，不是后期补丁
5. **开源优先，不重复造轮子**：通用功能模块先检索 GitHub 成熟开源库，按维护活跃度、Issue 响应、许可证兼容、技术栈匹配四项选型，多候选对比后给推荐方案；只有无法满足、体积过大或存在安全风险时才自研并写明理由

# 第二部分 八大功能框架设计

## F1 模型接入框架（Model Framework）

**平台提供**：
- 统一 OpenAI 兼容 API 网关（`/v1`），七类能力抽象：对话 / 推理 / 图像理解 / 图像生成 / 视频生成 / 语音识别 / 语音合成 / 结构化决策
- 厂商 Adapter 机制：每家厂商一个适配器（OpenAI 兼容优先，非标厂商写协议转换层）
- 模型元数据管理：编码、能力标签、上下文长度、价格、上下架
- 路由与容错：按配置选模型、失败自动降级、token 计费埋点
- 用户自定义模型：自带 API Key 接入第三方或本地部署模型（OpenAI 接口标准）

**扩展点**：新厂商 = 新 Adapter；新能力 = 新接口抽象
**用户创造**：选型、切换、带 Key 接入自有模型
**治理**：模型上下架、价格管理、调用限额

## F2 提示词框架（Prompt Framework）

**平台提供**：
- 提示词编辑器：富文本、变量占位、字符/Token 统计
- **一键优化服务**：基于元提示词帮用户改写优化（平台级 AI 服务）
- 版本管理：提示词变更历史、灰度、回滚
- 效果评测工具：黄金测试集回归、A/B 对比（框架级工具，不碰内容）
- 模板基础设施：模板的存储/复制/版本/审核管道

**扩展点**：模板一键复制即实例化；提示词可被工作流节点引用
**用户创造**：应用设定（人设/技能/工作流/约束）、模板分享到模板中心
**治理**：模板审核、分类、质量分

## F3 知识框架（Knowledge / RAG Framework）

**平台提供**：
- 四种导入管道：文档（pdf/docx/md/txt/csv）、问答对（双列 CSV）、表格（多列 Excel/CSV）、网站（URL/sitemap/子页面递归）
- 三档解析策略：文本 / 增强（图文表格）/ 智能（图像识别模型兜底扫描件）
- 三种分段策略：智能 / 自定义（长度+分隔符+重叠度）/ 层级（保留文档结构）
- 混合检索：语义（向量相似度）+ 全文关键词（BM25）双路，可调配比
- 全参数检索策略：相似度阈值、语义/全文条数、未命中策略（自由发挥/固定文案/转人工）、引用来源展示、查询改写（指代消解）、结果重排
- 检索测试工具：模拟提问、相似度可视化
- 定时同步：网页/在线文档增量同步

**扩展点**：解析器可插拔、Embedding 模型可更换
**用户创造**：上传私有知识（产品手册/FAQ/简历/小说…）
**治理**：容量配额、版权合规、导入频次限制

## F4 工具框架（Tool / Plugin Framework）

**平台提供**：
- 内置通用工具集（开箱即用，约 20 个）：当前时间、计算器、搜索（默认/AI/谷歌/必应）、网页速读、内容总结、天气、快递、新闻早报、文生图（多模型）、图像识别、文件生成、图表生成、AI 改图、AI 视频生成
- Function Calling 意图路由：工具描述匹配 + 关键词（前缀/包含/后缀）兜底
- 执行可观测：工具调用链、思考过程可视化
- **MCP 协议支持**：MCP Server 一键转为插件（地图/搜索等生态）
- **自定义插件**：OpenAPI/YAML 描述接入自有/第三方服务；贡献插件机制

**扩展点**：工具即插件，注册即用；工具市场
**用户创造**：自定义插件、贡献插件
**治理**：插件审核、安全沙箱、按次计费

## F5 流程框架（Workflow Framework）

**平台提供**：
- DAG 编排引擎：可视化画布、拖拉拽、连线、缩放
- 节点体系（12 种内置，注册即可扩展）：
  - 基础：开始/结束、大模型、智能体（调用已建应用）、知识库、插件、代码块（Python/JS）
  - 分支：意图分支（LLM/决策模型）、逻辑分支（变量判断）
  - 个性：固定回复、渠道发送、转人工
- 变量系统：节点间数据流转、全局变量
- 运行调试：全流程运行、单节点运行、对话运行、定时自动运行（自然语言配时间规则）
- 发布接入：发布到广场、托管渠道、自建部署、API

**扩展点**：新节点类型注册；节点可组合成"超级智能体"
**用户创造**：编排自己的流程型应用
**治理**：发布审核、版本管理、执行配额

## F6 接入框架（Channel Framework）

**平台提供**：
- 统一消息模型：文本/图片/语音/文件/素材（小程序卡片/名片）统一抽象
- 渠道适配器：微信公众号（企业/个人）、微信客服、微信、企业微信、企微应用、企微智能机器人、飞书、钉钉（流式输出）、QQ、网页嵌入 SDK、海外渠道（WhatsApp/Discord/Telegram/Slack/HubSpot）、硬件交互 API（HTTPS+WebSocket）、智能语音模组
- 长连接容灾：断线重连、消息补偿、离线监控通知
- 接入管理：渠道配置、触发条件、欢迎语、群聊绑定、限流

**扩展点**：新渠道 = 新适配器
**用户创造**：无（使用平台渠道能力）
**治理**：渠道配额、风控合规

## F7 分发框架（Distribution Framework）

**平台提供**：
- 模板中心：官方/用户模板存储、一键复制实例化、在线体验
- 应用广场：公开应用列表、分类体系（可配置）、搜索、收藏、官方认证标
- 推荐与排行：热度/质量分算法、分类筛选项
- 公开开关与创作者收益：应用公开→广场曝光→按使用量结算积分收益

**扩展点**：分类体系可配置；排行算法可替换
**用户创造**：应用、模板、灵感（Studio 画布可发布为灵感）
**治理**：内容审核、质量分、反刷量

## F8 变现框架（Monetization Framework）

**平台提供**：
- 版本体系：四档套餐（基础/标准/专业/企业）+ 权益矩阵 + 配额校验（功能开关 + 用量上限）
- 积分钱包：余额、签到、充值（多档套餐包）、消耗明细、余额提醒
- 订单与对账：订单记录、每日对账校准
- 收益结算：应用创作收益按 code 记账、提现规则
- 使用记录：全维度消耗流水（来源/应用/模型/Token/积分/耗时）
- 数据看板：调用、消耗、分布、明细下钻导出

**扩展点**：套餐权益可配置、计费规则可插拔
**用户创造**：公开应用参与收益分成
**治理**：防刷、对账、财务合规

## 6.1 框架化的四个机制（复刻成败关键）

**① 适配器注册机制**：所有品类（模型厂商/渠道/解析器/节点/插件）实现统一接口，注册进注册中心，运行时按 key 发现。加品类不动内核。

**② 用户创造的数据流**：
```
用户输入(提示词/知识/插件/流程) → 框架实例化 → 审核 → 发布分发 → 使用计量 → 收益结算
```
平台只维护这条管道，管道里流什么内容是用户的事。

**③ 参数透传机制**：框架参数（检索阈值/分段长度/温度/上下文/执行策略）从应用配置一路透传到运行时，平台不预设最佳值，只提供默认和测试工具。

**④ 治理内建机制**：审核、配额、质量分、排行不是后期补丁，而是框架层同级服务——用户创造的量越大，治理越要先行。

## 6.3 技术难点与对策

| 难点 | 对策 |
|---|---|
| 模型成本与延迟 | 语义缓存、流式优先、轻量模型分流（意图识别） |
| RAG 效果不稳定 | 全参数暴露 + 检索测试工具 + 黄金集回归，把调优权交给用户 |
| 插件误触发 | 意图+关键词双通道、执行过程可视化 |
| 上下文溢出 | 预算管理器、查询改写减负 |
| 渠道协议碎片化 | 统一消息模型 + 适配器 + 断线补偿 |
| 计费准确性 | 原子服务 + 双写对账 |
| 工作流可靠性 | 节点幂等、执行快照、失败重试 |
| 用户内容风险 | 审核管道前置（发布前机审+人审）、质量分、反刷量 |

## 7.1 里程碑

| 阶段 | 周期 | 出口标准 |
|---|---|---|

## 7.2 风险与缓解

1. **框架表达力不足**（最大风险：用户用框架造不出好东西）→ Phase 1 用官方示例包反向验证框架能力，缺什么补什么
2. **AI 效果不及预期** → AI 架构师前置，Phase 0 建黄金评测集，每迭代回归
3. **冷启动困境**（没有用户就没有内容）→ 官方种子模板 + 定向邀请种子创作者 + 公开收益激励
4. **范围蔓延** → 严格按 ★/☆/○ 执行，MVP 只做 42 项
5. **合规周期**（等保/算法备案）→ 第 1 月启动，预留 2-3 个月
