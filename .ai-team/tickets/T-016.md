# T-016 契约合规缺陷：微信扫码通道补协议签署约束（GAP-CONTRACT-004）

## 关联
- 功能 ID：B-01（账户体系）/ 合规
- 契约版本：v0.1.1 → v0.1.2
- 负责角色：contract-engineer（何约）——合规语义变更按纪律只能契约所有者改，主理人不代管
- 依赖：无
- 状态：DONE（2026-10-14，分支 fix/contract-v0.1.2 @ 2019e54）

## 背景（qa-reviewer 发现，主理人独立核实并上调严重性）
`agreementAccepted` 在整个 console-api.yaml 只出现 2 处，均在 loginByPhone（请求 required + 定义）。微信扫码两端点与 /auth/refresh 均无该约束。**这不是实现漏了，是契约层从未定义**——微信通道从设计起就没有协议签署要求。协议签署是法律效力前提，微信扫码是默认登录方式，带入生产属合规事故。

## 修复要求（契约层，v0.1.2）
1. `POST /auth/wechat/qrcode` 请求体增加 `agreementAccepted`（required boolean）——与 loginByPhone 同模式；false 时 403 AGREEMENT_NOT_ACCEPTED
2. `GET /auth/wechat/qrcode/{ticket}` 的 confirmed 响应：创建时未签协议的不得下发 TokenPair（403 AGREEMENT_NOT_ACCEPTED），description 补充说明
3. 各登录通道约束一致性：phone 与 wechat 两个登录通道的协议约束必须同构（QA 守卫 tests/contracts 已改为"约束不一致即报"，修完自动转绿）
4. CHANGELOG 增 v0.1.2 条目（注明合规修复属性）
5. `npm run generate` 重生成双 SDK 并同 commit；`npm run lint` 零 error
