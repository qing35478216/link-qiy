## 交付说明

### 改了什么（分支 feat/T-002-account，工作目录 wt-T-002）
四层实现（api → services → domain ← infra，infra 实现 domain 协议）：

- **api/**：`health.py`（GET /healthz）、`auth.py`（/auth/wechat/qrcode、/auth/wechat/qrcode/{ticket}、/auth/phone/sms-code、/auth/phone/login、/auth/refresh、/auth/logout）、`users.py`（GET/PATCH /me）、`deps.py`（每请求组装 + 事务边界 + bearer 鉴权，X-Tenant-Id 与令牌 tid 不一致 → 403 TENANT_MISMATCH）、`errors.py`（契约 Error 体统一映射：AGREEMENT_NOT_ACCEPTED→403、INVALID_TOKEN/REFRESH_TOKEN_REVOKED→401、USER_NOT_FOUND→404、VALIDATION_ERROR→422）、`schemas.py`（Pydantic 模型，PATCH /me `extra="forbid"` 落实 v0.1.1 readOnly：id/plan/agreementAcceptedAt 携带即 422）
- **domain/**（纯 Python）：`users.py`（User 聚合、Plan 四档、手机号严格校验、协议幂等接受）、`auth.py`（TokenPair/Principal/TokenClaims、TokenService/WechatProvider/SmsProvider 协议、领域异常）、`rules.py`（协议校验、刷新令牌可用性纯规则）、`events.py`（DomainEvent/UserCreated/MessageBus）、`repositories.py`（UserRepository/AccountDirectory/RefreshTokenStore/SmsCodeStore 协议，tenant_id 写进签名）
- **services/**：`auth_service.py`（登录编排：微信扫码 confirmed→登录/注册；手机号发码/验码/协议；refresh 轮换吊销旧 jti；logout 吊销全部；新用户发 UserCreated）、`user_service.py`（GET/PATCH /me）
- **infra/**：`jwt_service.py`（PyJWT，HS256 白名单、sub/tid/typ/jti claims、leeway 支持）、SQLAlchemy 仓储三件（users/account_index/refresh_tokens，仓库层强制 tenant 过滤）、`wechat_mock.py`（票据状态机 + 可选自动确认，仅联调）、`sms_mock.py`（验证码进日志）、`sms_code_store.py`（TTL+5 次尝试上限+一次性）、`bus.py`（内存 MessageBus）、`logging.py`（structlog JSON + OTel trace_id）、`config.py`（env 配置）
- **alembic/**：0001_account 初始迁移（通用类型，PG16/SQLite 双跑验证通过）
- **tests/**：domain 6 组 + infra 2 组 + api 12 组，共 58 用例

### 怎么验证的
- `uv run pytest`：58 passed；domain 覆盖率 99.48%（≥70% 门禁）
- `uv run ruff check .` / `ruff format --check .` / `black --check .` / `uv run mypy`（strict）：全过
- `uv run alembic upgrade head`（sqlite 冒烟 + PG 语法通用类型）通过
- curl 端到端（uvicorn 起服务，sqlite 库 + 迁移）：healthz=200；sms-code=204；agreementAccepted=false→403 AGREEMENT_NOT_ACCEPTED；登录→TokenPair；GET /me→UserProfile；PATCH /me 携带 plan→422；PATCH nickname→200；refresh→新对；旧 refresh 再用→401 REFRESH_TOKEN_REVOKED；logout=204 后 refresh→401；篡改尾字符令牌→401；微信 qrcode→pending→scanned→confirmed+TokenPair→/me 200

### 风险点
1. **SQLite 冒烟替代 PG 联调**：时间列 naive/aware 已在 infra 用 ensure_aware 归一；接 PG 后需重跑一遍 /auth 全链路确认
2. **内存态票据/验证码**：Phase 0 单实例；多实例部署前必须换 Redis（协议已预留，SmsCodeStore/WechatProvider 不变）
3. **access token 无即时吊销**：logout 只吊销 refresh（契约语义）；如需 access 秒级失效需引入 jti 黑名单（Redis），已在 ADOPTED-TOOLS 记录
4. **脚手架来源**：scripts/new-service.sh 在 feat/T-000-infra 分支未合入 main，本单按 T-000 模板手工等价生成（内容一致）；建议 T-000 合入后删除本备注
5. **沙箱限制**：pytest 需 `--basetemp`（共享 /tmp 并发 mkdir 被拒），已写进 README
