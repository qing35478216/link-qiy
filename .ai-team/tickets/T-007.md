## 交付说明

### 改了什么
四层全链路（`services/billing`，模块 `linkai_billing`）：

**domain（纯 Python，零框架，AST 守卫）**
- `wallet.py` 积分钱包（整数积分/非负/提醒策略）；`ledger.py` 流水（append-only，delta 有符号，blocked 留痕，row_id 分页游标）
- `pricing.py` 四档充值套餐（docs/01 第十部分实测：1000/¥2.90=290 分、10000/¥19.00=1900、100000/¥170.00=17000、500000/¥800.00=80000）+ 签到 57 积分/日 + 订单超时 30min + 回调重放窗 300s
- `orders.py` 订单状态机（pending→paid→refunded / pending|paid→closed；非法流转 OrderStateError）
- `quota.py` 四档权益矩阵（docs/01 实测：应用 3/10/30/不限、工作流 2/6/15、插件 3/10/30、超级助理 0/3/9、云电脑 0/1/3、知识条数 2000/20000/100000、数据库行数 5k/50k/200k、团队 10 人、11 项功能开关、月度积分 None/3万/100万/None）
- `metering.py` MeteringEventIn（消费侧 DTO，幂等键=event_id，双传输兼容：JSON int + Redis Stream 字符串）
- `reconciliation.py` 对账纯函数（missing_in_db/missing_in_stream/amount_mismatch/blocked 四分类，差异率>0.01% 告警）
- `ports.py` 全部仓储/流水/支付/时钟协议；`errors.py` 12 个领域错误（稳定 code + HTTP 映射 + details 契约）

**services（应用层，零框架 import——资金域加严）**
- `metering_service.py`：process() 原子扣减编排；ingest/drain（XADD→消费→ACK，至少一次+幂等）
- `wallet_service.py`：余额/签到（幂等双保险）/提醒阈值/plan 同步
- `order_service.py`：下单（金额以套餐为权威，客户端传金额无效）/回调（验签+重放+幂等）/关单
- `quota_service.py`：/quota/summary 真实数据（本月用量聚合，排除 failed）/权益校验
- `usage_service.py`：全维度流水 + cursor 分页；`reconciliation_service.py`：对账编排 + 留痕

**infra**：ORM 5 表 + 迁移 0001_billing；`wallet_repo.py` **资金写路径核心**（SAVEPOINT 内流水 INSERT 幂等 + 条件 UPDATE 原子扣减 + blocked 留痕 + 防篡改比对）；redis_stream（生产）/memory_stream（dev）；payment_mock（HMAC-SHA256 规范化签名 + compare_digest + 重放窗）；jwt 校验；recon_run_store。

**api**：控制台面 10 端点 + 内部面 5 端点（见 README 表）；统一错误响应（code/message/requestId/details）。

### 怎么验证的
- **pytest 156 passed**（`--basetemp=/tmp/xxx` 沙箱）；domain 覆盖率 **96.5%**（门禁 70%）
- **★扣减幂等并发用例（验收②）**：10 线程 + Barrier 统一发令 + SQLite 文件库独立连接（真实写竞争，非单连接假并发）——同 request_id 并发 10 次：**恰好 1 次 APPLIED、9 次 DUPLICATE，余额 10000→9900 精确**；10 个不同事件抢 500 积分：恰好 5 成 5 blocked，余额 0 绝不为负；并发签到 10 线程同日只加 57 一次
- 幂等/对账其他：同 eventId 重复投递 5 次只扣一次；重复回调 credited=False；篡改金额/伪造签名/超窗回调全部 401 PAYMENT_VERIFY_FAILED；blocked 终态化（充值后重试同 request_id 返回 DUPLICATE 不补扣）
- 金额精度：套餐积分/分逐档断言实测值；领域层类型即约束（float/负数构造即抛）；**零浮点金额**（ruff/mypy 全绿，无 float 字段）
- 配额超限（验收④）：403 QUOTA_EXCEEDED + details{dimension,limit,used,increment,plan}；功能未开 FEATURE_NOT_AVAILABLE
- 对账（验收⑤）：内存 Stream 一致不告警；注入丢失事件 → missing_in_db + alert + frozen_settlement + reconciliation_runs 留痕；fakeredis 驱动 Redis 路径语义（append/read_group/ack/重投）
- 架构守卫：AST 静态扫描——domain 零框架 import、services 零框架 import、依赖只向内、ORM 只在 infra
- **ruff 全绿 + mypy --strict 43 文件零错误**；alembic upgrade/downgrade 冒烟通过（SQLite）

### 风险点（人工复核项）
1. **双人评审未完成**：资金 PR 按宪法必须 Reviewer + 人类抽查后才可合并——当前仅实现者自验通过
2. **SQLite 冒烟限制**：并发用例在 SQLite 文件库验证（SQLAlchemy 渲染相同 SQL 形态）；PG 上行锁串行化语义更强，合入后需在 compose 环境（PG16）复跑一次并发用例
3. **同 request_id 内容不一致判定**：比对 kind+credits_charged（不比对 delta——blocked 条目 delta 归零是设计行为）；若未来出现"同键不同业务"的合法场景需重新评估
4. **UTC 日期口径**：签到"日"与月度用量均按 UTC（链路统一）；若产品要求北京时间换日需显式改 date_key 并回归
5. **内存 Stream 仅限单进程**：REDIS_URL 未配置时多实例流水不互通（README/.env.example 已警示）；生产必须配 Redis
6. **Mock 支付**：pay_order 端点Phase 0 仅供联调；生产需换真实渠道适配器（端口已冻结）并关闭该端点
