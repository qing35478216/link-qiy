**核心机制**

- **注册机制（铁律 4）**：加厂商 = ① 写一个实现 `ProviderAdapter` 的类 ② 在 `BUILTIN_ADAPTERS` 加一行
  ③（可选）在 `catalog_seed.py` 加卡片。**domain/services/api 零改动**。另提供 `register_builtins(extra=...)`
  让外部包连`BUILTIN_ADAPTERS` 都不用改。`TestZeroKernelChange::test_kernel_has_no_provider_branching`
  用 AST 扫描内核，防止有人后来写 `if provider == "openai"`。
- **降级链**：顺序来自 `ModelCard.fallback_codes`（平台不预设"最佳策略"）；只对 `retriable` 错误降级
  （5xx/超时/429 降级，4xx 语义错误/凭证缺失/SSRF 拦截直接失败）；降级配置成环有去重保护；
  **流式只在首片产出前允许降级**（已吐内容不能静默换模型）。
- **计量（红线）**：`ModelInvocationService` 是唯一持有 `AdapterRegistry` 的地方，api 层拿不到注册表，
  物理上杜绝绕过。成功与失败**都**发事件（失败 `credits=0` 但留痕以对账）。厂商不回 usage 时用
  启发式估算器兜底（中文按字计，避免按 4 字符/token 严重低估）。
- **SSRF（铁律 5）**：`infra/ssrf.py` 阻断 http/内网网段/元数据端点/解析到内网的域名，
  不跟随重定向，白名单校验，响应体上限。架构守卫测试禁止适配器直接 import httpx。

### 2. 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 厂商接入方式 | **统一 OpenAI 兼容 HTTP，不引入任何厂商 SDK** | 许可证风险 + 依赖体积 + 维护成本，详见 ADOPTED-TOOLS.md §2 |
| 网关内核 | **自研，不采用 LiteLLM** | LiteLLM 内核含100+ 厂商 if/elif 分派，与铁律 4"内核零改动"**正面冲突**（死结）；且自带价格表造成契约双事实源。详见 ADOPTED-TOOLS.md §0-1 |
| 出网客户端 | httpx（唯一新增库） | 原生 async（流式硬需求）+ 可显式禁用重定向（安全约束） |
| 用户 API Key 校验 | **model-proxy 不验，信任网关注入的 `X-Tenant-Id`** | 若自己查库验 Key 就违反"跨服务禁止直接查库"（docs/03 §3.1）。Key 签发归 platform |
| Playground 计量 | **与业务调用完全一致** | 否则 Playground 就是免费刷模型的漏洞 |

### 3. 怎么验证的

**5 个自验用例覆盖全部 6 条验收标准，全部零触网**
（`tests/conftest.py` 有 autouse 护栏在 **socket 层**拦截真实出网，漏 mock 立刻炸）：

| 验收标准 | 用例位置 |
|---|---|
| 1. 5 家适配器回放 | `test_adapters.py`：5 家 × 非流式/请求形态/流式终局/429/5xx/4xx不可重试/畸形响应；Anthropic 另有 6 项协议翻译断言 |
| 2. 零内核改动 | `test_registry.py::TestZeroKernelChange`（3 例，含 AST 守卫）+ `test_architecture_guard.py`（13 例） |
| 3. 降级链 | `test_fallback.py`（22 例：主备切换/三级级联/全失败/不可重试不降级/凭证缺失快速失败/重试后降级/流式两种降级时机/降级成环） |
| 4. 计量埋点+契约 | `test_metering.py`（含 `TestMeteringEventContract` 字段契约测试、`TestMeteringIsUnbypassable`） |
| 5. 无 SDK 直连 | `test_architecture_guard.py::TestEgressGuard`（AST 扫 httpx import 白名单） |
| 6. 不绕计量 | 同上 + `test_api.py::test_playground_completion` 断言 Playground 也产生事件 |
| SSE 协议 | `test_sse.py`（9 例：事件序列/done 携 credits/信封必填字段/seq 单调/异常终局） |

**过程中被用例抓出并修复的 3 个真实缺陷**（非"改测试让它过"）：

1. **计费漏计（资金相关，最严重）**：`CreditCalculator` 的噪声精度取 1e-6，导致
   GLM Flash（0.0001/1k）这类极低单价在量化后被截断成 **0 积分**——等于免费调用。
   修为 1e-9，并加`test_rounds_up` 固化。
2. **流式少算账**：SSE `done` 事件在 credits 计算完成前就把终端分片 yield 出去了，
   客户端收到的 `usage.credits` 恒为 0。改为**扣住终局分片，待计量算完再 yield**。
3. **错误语义混淆**：`retriable` 被同时用来推导 HTTP 状态码，导致"候选耗尽"
   （`ModelCallFailure`，网关自身不该再重试）被误报成 400（客户端的错）。
   拆成三个正交维度 `code` / `retriable`（内部降级判断）/ `client_status`（对外语义）。

### 4. 顺带修正的工程问题

- 流式失败路径把"已产出分片数"当 `attempt` 上报，触发 `MeteringEvent` 校验失败。
- `mypy --strict` 需启用 `pydantic.mypy` 插件才能理解契约的 `Field(alias=...)`。
- 测试护栏最初打在 `httpx.AsyncClient.send` 与 transport 层，均被 respx 的patch 层级盖过，
  改打到 **socket 层**才真正兜住。

### 7. 开源选型结论（铁律 8，全文见 `services/model-proxy/ADOPTED-TOOLS.md`）

- **不采用 LiteLLM**（61k stars，MIT核心 + `enterprise/` 商业许可，GitHub 报 `NOASSERTION`；
  5505 open issues）。**主因不是许可证而是架构**：其`litellm/main.py` 含100+ 厂商
  if/elif 分派，新接厂商必须改上游内核，与铁律 4 正面冲突；且自带价格表与我们的
  `ModelCard` 目录构成契约双事实源。
- **不引入任何厂商 SDK**：逐家核查（openai-python Apache-2.0 / anthropic-sdk-python MIT /
  dashscope 许可未清晰标注 / zhipuai-sdk-python-v4 MIT 但停滞 2025-10 / DeepSeek 无官方 SDK），
  4/5 家有 OpenAI 兼容端点。统一走公开 HTTP API 规避了 SDK 许可传染风险（商业厂商 SDK
  历史上出现过非商用条款变更）与数十个传递依赖。
- **唯一新增运行时依赖：httpx（BSD-3-Clause）**。强制只经 `infra/http_client.py` 使用，
  AST 守卫禁止其他文件 import。
- 全部依赖为 MIT/BSD/Apache-2.0，**无 GPL/AGPL/非商用许可**。
