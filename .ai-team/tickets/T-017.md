## 背景（runtime-engineer T-004 交付时上报）
刘畅的对话引擎 v1 已落地（main @ aeeeb1f），执行链两步落库可回放，但 service-api.yaml **没有调试窗所需的读端点**：
- 调试窗需要 `GET /v1/conversations`（会话列表，cursor 分页）
- 执行链回放需要 `GET /v1/traces/{traceId}` 或 `GET /v1/conversations/{id}/events`（事件序列查询）

前端调试抽屉与控制台调试窗无契约可依。

## 修复要求（契约层，追加式）
1. service-api.yaml 增补上述端点（具体形态何约定：路径风格与 console-api 的 cursor 分页保持一致；事件查询端点的事件 schema 引用 runtime-events.yaml 的 RuntimeEvent 联合）
2. 多租户：经 API Key 归属限定（调用方不传 tenant）
3. CHANGELOG 条目；spectral 零 error 后 `npm run generate` 重生成双 SDK 同 commit
4. 与 T-016（微信协议门，v0.1.2）合并发布或紧随其后，版本号连续即可

## 验收标准
1. spectral 零 error；oasdiff 无 breaking（纯追加）
2. SDK 生成物含新端点；刘畅的 services/runtime 按其实现有契约可依（下游注意里说明 runtime 侧要补的端点实现）
